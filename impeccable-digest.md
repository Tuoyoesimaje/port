# Impeccable teaching digest

Source repository: `skills-main/impeccable-main`.

## Repository README

### `README.md`

**Purpose.** Introduces Impeccable as design vocabulary and review/detector tooling for coding agents; explains installation, commands, detector use, project files, and safety/privacy notes.

**Core ideas and command sequence**
- Install from the project root with `npx impeccable install`; reload the coding tool; run `/impeccable init` (`$impeccable init` on Codex). `init` reads the code, asks only what cannot be inferred (audience, product purpose, constraints), and writes `PRODUCT.md`. Later commands read it. Run `/impeccable document` to capture the existing visual system in `DESIGN.md`.
- Name a command and target; narrow targets are preferred because a single section reviewed closely beats a whole page at a glance. Example requests: `/impeccable critique the onboarding flow`, `/impeccable quieter the landing page`, `/impeccable polish settings`, `/impeccable harden checkout`, or `/impeccable redo this hero section`. `/impeccable pin audit` creates an `/audit` shortcut. Typing `/impeccable` alone displays commands.
- Build path: for new landing pages/showcase surfaces, either generate a full-fidelity comp then build to match (bolder, slower), or build directly in code (leaner, faster). App screens and documents are always built in code. `init` asks once and stores `buildPath` in `.impeccable/config.json`; the decision page can override it for one session; this choice appears only when the harness can generate images.
- Live iteration: `/impeccable live` opens a running dev server with an overlay; select an element, pick a direction, cycle through variants, accept one to write it to source. Supports Vite, Next, SvelteKit, Astro, Nuxt, and plain HTML. It edits a local checkout only: do not inject it into a deployed site or weaken production CSP. Applying copy edits runs the optional `package.json` script `impeccable:manual-edit-validate` with the user's permissions; review that script before live mode in an unfamiliar repo.

**Commands and reviews**
- There are 24 commands. Steer: `bolder`, `quieter`, `distill`, `colorize`, `typeset`, `layout`, `animate`, `delight`, `overdrive`. Review: `critique` (scored UX review), `audit` (technical quality report). Finish: `polish`, `harden` (errors, i18n, overflow, edge cases), `clarify`, `adapt`, `optimize`, `onboard`. Iterate live: `live`, `generate`. Plan/setup: `shape`, `init`, `document`, `extract`. The 24th, `craft`, is a deprecated alias for a plain build request.
- `critique` scores against usability heuristics and ranks fixes. `audit` checks accessibility, performance, theming, and responsive behavior, ranking findings P0 (blocking) through P3 (polish).
- The detector is deterministic (no LLM/API key). The README describes 62 rules flagging visual defaults/“slop” and quality issues such as cramped padding and skipped headings.

**Detector workflows and exact examples**
- Agent hook: scans every UI file the agent edits and reports findings before the work is called done. Available on Claude Code, Cursor, Codex, GitHub Copilot, Grok Build, and Hermes Agent; installer sets it up. README says “Say yes.”
- CLI: `npx impeccable detect src/` scans a directory; `npx impeccable detect https://example.com` scans a rendered page (installed Chrome or Edge); `npx impeccable detect --json .` emits machine-readable output; `npx impeccable detect --github src/` emits GitHub Actions annotations; `npx impeccable detect --list-rules` lists every rule ID and description. JSX/TSX source gets pattern rules only; rendered-page rules (e.g. low contrast and tiny text) run on a URL, e.g. `npx impeccable detect http://localhost:5173`.
- Exit code `2` means findings; `1` means target could not be scanned. Allow a brand font everywhere with `npx impeccable ignores add-value overused-font Inter --reason "Brand font"`. Disable a rule for one file with `<!-- impeccable-disable overused-font: exported brand doc -->`.
- Browser: Chrome extension overlays the same findings on a live page.

**Installation and tool support**
- `npx impeccable install` detects coding tools, asks project vs global scope, offers the design hook where supported, and should be followed by reloading the tool. `npx impeccable update` refreshes an install. Script options: `--providers=claude,codex,cursor` and `--scope=project|global`.
- Before the hook runs, Codex users approve it via `/hooks` (again after an update changing it); Grok Build uses `/hooks-trust` or `--trust`; Hermes Agent enables plugin `impeccable-design-hook` once with `hermes plugins enable impeccable-design-hook`. Node is needed only for `npx`; the skill runs a self-contained engine binary that ships with it or downloads to `~/.impeccable/bin/`.
- Claude Code plugin install: `/plugin marketplace add pbakaus/impeccable`, then open `/plugin` and install. VS Code: Marketplace or `code --install-extension renaissance-geek.impeccable`; requires VS Code 1.109.3+, Copilot Chat, and trusted workspace; it installs the skill without the hook. Grok: `grok plugin install pbakaus/impeccable#plugin --trust`.
- Team pinning: `git submodule add https://github.com/pbakaus/impeccable vendor/impeccable`, then `npx impeccable link --source=vendor/impeccable --providers=claude,cursor`; commit `.gitmodules`, submodule, generated links. Teammates use `git submodule update --init --recursive`. Upgrade with `git submodule update --remote vendor/impeccable`, rerun `link`, and commit. Linking installs skills, not hooks; existing skill folders remain unless `--force` is passed.
- Manual copies skip the design hook and subagents; run `npx impeccable install` to get them. OpenCode additionally needs `.opencode/commands/impeccable.md`; Hermes requires `hermes skills trust` for project-local skills; Cursor/Gemini CLI may require Agent Skills enabled; restart Trae after copying. `install`/`update` manage DeepSeek Harness global copy only when `DSH_HOME` is inside the home directory.

**Project artifacts, cautions, and privacy**
- Shared `.impeccable/` artifacts to track: `config.json`, `live/config.json`, `design.json`, `surfaces/*.md`, `critique/*.md`; also keep `PRODUCT.md` and `DESIGN.md`. Other files are screenshots, caches, and runtime state. README supplies ignore patterns for local config, hook caches/pending files, PNGs, review/questions, live sessions/previews/annotations/cache/manual-edit state and related outputs. A `.gitignore` cannot untrack an already tracked file; run `git rm --cached <path>`.
- Claude Code command hooks run outside model approval, including when model commands are denied; first edit can download engine. Review installed hooks before unattended runs, or disable all with `--settings '{"disableAllHooks": true}'`. Installer leaves hooks it did not add alone.
- Telemetry: starting a new design fetches visual directions from impeccable.style. Turning telemetry off stops anonymous recording of directions shown/picked, **not** the catalog request. Project name, files, code, and `PRODUCT.md` are never sent. Disable with `npx impeccable telemetry off`, `DO_NOT_TRACK=1`, or `"telemetry": false` in `.impeccable/config.json`.
- `/impeccable doctor` finds stale context files, unused settings, and broken hooks. License: Apache 2.0; project started from Anthropic's `frontend-design` skill.

**Opinionated positioning from README.** Impeccable is strongest on existing interfaces: point at a page/component and iterate. New pages are supported but harder; the README directs users to “Build something new” docs.

## Impeccable skill

### `plugin/skills/impeccable/SKILL.md`

**Purpose.** Top-level operational contract and router for design work, commands, modes, context, hooks, and agent behavior.

**Non-negotiable quality and workflow rules**
- “Finish the job. No hedging, no shortcuts: the deliverable is complete, except assets the user must provide.”
- Scale ambition to surface mode: Persuade and Experience receive full commitment; Operate and Read express ambition through precision/restraint, and familiar patterns must earn their place.
- Verify the rendered result at shipping sizes and batch checks: fix what one look shows before looking again instead of screenshotting after every tweak.
- Exact setup order: (1) once per session run `"${CLAUDE_SKILL_DIR}/scripts/impeccable" context` from the user's project cwd; `${CLAUDE_SKILL_DIR}` is the directory containing this `SKILL.md`, not a plugin root two levels above. Resolve every launcher call against that directory. On Windows without `sh`, use `& "${CLAUDE_SKILL_DIR}/scripts/impeccable.cmd"`. The self-contained binary ships beside the launcher or downloads on first run; Node/other runtime is not required. For named source/route pass `--target <path>`. Context loads PRODUCT.md, DESIGN.md, matching surface brief, and native-platform guidance when applicable; follow directives and do not rerun context.
- Then (2) load the playbook: Commands-table reference for explicit/implied subcommand, or `reference/new-work.md` for a new surface/replacement visual world. Inspect target and incumbent visual truth before editing. If app cannot run, begin with committed visual-regression goldens/screenshot fixtures; verify target and freshness against current tokens, CSS, components, or assets, resolve conflicts, compare theme/variant captures.
- Then (3) after resolving analysis/direction, read `reference/craft-floor.md` immediately before **any UI edit, including small refinements**. It contains the quality floor, absolute bans, and reflexes not caught by detector. Do not load for planning-only work.
- If launcher refuses/fails, before the next tool call send exactly: “Context loading did not run; I’ll read the existing project context directly.” Then read existing PRODUCT.md and DESIGN.md without inventing missing context; follow steps 2–3 including craft-floor immediately before UI edits; continue with permitted tools. Applies to planning and editing; launcher failure alone does not block either.

**Design rules**
- “The brief wins.” Honor pinned aesthetics, eras, materials, fonts, and palettes even when they conflict with a saturated-pattern warning; redirecting a clear brief toward your taste is failure.
- Refinement preserves incumbent identity, behavior, copy, and everything out of scope. Ask before replacing factual copy or adding claims.
- Redesign preserves product truth, content, function, native affordances, and constraints, but treats old look as evidence/anti-reference; choose replacement world in new-work and replace DESIGN.md. Never split the difference by polishing the discarded look.
- “Loaded symbols stay out of the decoration.” A subject's world does not license emblems tied to militarism, supremacy, or hate movements as motifs/badges/ornament (examples: Rising Sun rays, Confederate battle flag, Nazi-era insignia and stylised variants); use neutral forms. Documented factual content containing such a symbol stays unchanged.
- Visual authority is evidence, not a filename. Missing DESIGN.md alone does not mean greenfield; new-work decides whether to preserve, expand, or replace incumbent world.

**Surface modes**
- **Persuade:** visitor decides and acts; design is product (landing/marketing/campaign/pricing); earn attention/action, ship real imagery when brief needs it, follow committed world not category habit.
- **Operate:** visitor completes task (app UI, dashboards, editors, admin, settings, tools); scanability, consistency, native expectations, real usage scene outrank expression; brand lives in precise details.
- **Read:** visitor understands (docs/articles/guides/help/changelogs); structure for comprehension, then make reading worth staying for.
- **Experience:** visitor is inside work (portfolios/galleries/showcases); artifact leads from first viewport; interface recedes.
- Choose mode from requested surface, not product; persist only in that surface brief. Examples: a tool landing page is Persuade; fashion-house documentation is Read; docs index is Read, not Persuade. For new surfaces see new-work; Operate/Read detail in operate.

**Command routing and order**
- Commands table: `craft [feature]` deprecated alias for ordinary new-work; `shape [feature]` plans UX/UI before code; `init` captures durable product context in PRODUCT.md; `document` generates DESIGN.md from project code; `extract [target]` pulls reusable tokens/components into design system; `critique [target]` heuristic-scored UX review; `audit [target]` technical checks (a11y/performance/responsive; native uses audit.native); `polish`, `bolder`, `quieter`, `distill`, `harden`, `onboard`, `animate`, `colorize`, `typeset`, `layout`, `delight`, `overdrive`, `clarify`, `adapt` (native variant where relevant), `optimize`, `live`, and `generate [n] [action] [element]` each route to their named reference.
- No argument: read `reference/routing.md` and present context-aware menu; **never auto-run a command**.
- Explicit/clearly implied command: load its reference (native variant on native platforms) and follow it. Ask once if two commands fit.
- Workflow/command-selection question: read Workflow questions in routing.md.
- Otherwise general design work: missing PRODUCT.md means route new surface/replacement world through init, then new-work; narrow refinement of existing code proceeds on incumbent implementation per `impeccable context`, offering init afterward instead of blocking.
- `teach` aliases init. `craft` adds nothing beyond ordinary new-work. `shape` owns task discovery, then enters new-work only for visual-world and surface-concept decisions.
- After init writes PRODUCT.md, resume without rerunning context. Init loads native platform reference itself if recorded platform is `ios`, `android`, or `adaptive`.
- Pin/unpin workflow: `"${CLAUDE_SKILL_DIR}/scripts/impeccable" pin <pin|unpin> <command>` creates/removes standalone `/<command>` shortcut. Report script result concisely; relay stderr verbatim on error.
- Hooks: `/impeccable hooks <on|off|status|ignore-rule|ignore-file|ignore-value|reset>` manages project design-detector hook (runs after UI file edits and surfaces findings). Load `reference/hooks.md` when invoked with any argument.
- Doctor: `/impeccable doctor` reports/repairs drift between PRODUCT.md, DESIGN.md and sidecar, config, surface briefs, hook, and what this version reads. Load `reference/doctor.md` when invoked or asked what is stale/out of date/needs refreshing. `CONTEXT_STALE` is the cheap subset: act per its instructions, do not run doctor unasked.
- **“Never repair drift as a side effect of a design task.”** A `CONTEXT_STALE` finding is reported, not acted on, unless asked. Exception: a finding marked `auto` is performed by the next write to that file.

### `reference/craft-floor.md`

**Purpose.** Required just before UI edits after direction is settled; sets implementation-quality floor and hard bans. A pinned brief/committed visual world overrides everything except a line marked ban; personal habit does not. When hook is active, it enforces mechanical checks; act on findings rather than re-auditing each rule.

**Verify together on each batched render** (checks are built-result checks, not intentions; one render, not separate screenshot trips):
- Contrast: body and placeholder ≥4.5:1; large text ≥3:1. On colored surfaces, tint secondary text from that hue or the foreground; **never gray**.
- Depth: shadows need offset and soft blur; zero-offset colored halo is decoration.
- Spacing: tight groups, generous separation, more space above heading than below; read computed values.
- Type: body measure 65–75ch; display max 6rem; tracking floor -0.04em; balanced headings; obvious scale/weight steps. Test real copy at every breakpoint and fix overflow.
- Motion: one authored moment, not scattered effects or identical entrance on every section. Exponential ease-out from an already-visible default. Blur, backdrop-filter, clip-path, mask, and shadow are allowed if smooth; reach beyond transform/opacity.
- States: hover, disabled, loading, error, empty; also real content, working controls, responsive composition, keyboard focus.
- Browser surfaces: theme text selection, caret, custom scrollbars, focus rings, underline offset, and tabular numerals from palette; defaults do not belong to a design system.
- Copy: product's own language; controls name action; errors name problem and recovery.
- Coverage: every brief requirement present and findable within seconds.

**Refuse list (defaults, unless brief earns them; rewriting means replace the element, not soften it):**
- Same-size cards of icon + heading + text as page structure; cards are lazy containers and nested cards are always wrong.
- Hero-metric template: big number, small label, supporting stats, accent.
- **Kicker/eyebrow above heading is an absolute ban; no brief earns it back.** Delete label; heading carries its own weight.
- Section numbers (01 / 02 / 03) unless sequence conveys needed information.
- Modal for a task needing neither interruption nor protected focus.
- Gradient text (emphasize with weight or size).
- Glass/blur as decoration rather than specific effect.
- Colored `border-left`/`border-right` above 1px on cards, list items, callouts, alerts.
- Hard offset shadows (`box-shadow: 4px 4px 0`) outside an actually neobrutalist world; zero-blur block shadow is costume, not depth system.
- Sparklines, progress rings, soft-shadowed rounded rectangles standing in for content.
- Monospace as “technical” costume instead of code/data/measurement.
- System display face (Impact, Arial Black, platform sans) as own-world page display voice: source/self-host a matching-character face; nearest installed font is a failure, not fallback.
- Unicode glyphs or emoji standing in for icon system; use real library or authored SVG, consistent stroke/weight.
- Geometric masks approximating organic photographic contours; derive alpha matte from actual image or make cut-out asset; approximation reads worse than omission.
- Light/dark picked by category; choose from use scene (who, where, ambient light).

**Direction rule.** Floor checks mechanics, never chooses direction. With checks green, spend page on committed world; when torn between refined and committed, commit.

### `reference/new-work.md`

**Purpose.** Full workflow for a new surface or replacement visual identity. PRODUCT.md owns product truth; DESIGN.md durable visual decisions; a surface brief strategy for a route/artifact. If PRODUCT.md is missing, complete init first; missing DESIGN.md alone does not route back to init. This is the longest playbook; the exact ordering below is significant.

**1. Decide what is true.** Read DESIGN.md, representative code, tokens, components, assets. Redesign preserves product truth/content/function/constraints/explicit brand commitments but replaces old visual world; old look is evidence, not authority. Established world is inherited even without DESIGN.md (document it rather than inventing); incomplete brand preserves confirmed assets/recognizable traits and expands with user; no visual authority creates a world with user. A local section/component/feature/state inherits established surface; never make local addition a new identity exercise.

**2. Ask before implementation.** Use structured question tool when available; ask 2–3 related questions, compact confirmation for precise request. Skip settled facts, not confirmation: DESIGN.md settles world, not this surface's purpose/concept. Persuade asks who acts, belief, real proof/content/assets; Operate task/information/states/frequency/constraints; Read reader question/source/structure/wayfinding; Experience lead/exploration/interaction/transition. All modes ask success, what remains untouched, and what would make polished result feel wrong. Never ask for CSS values or canned aesthetic lanes.

**3. Set invention scope.**
- Existing-surface extension inherits world/composition; resolve only new purpose/content/hierarchy/states/interaction/join to experience. No concept tournament or DESIGN.md change unless user approves durable system change.
- Whole surface inside established world keeps visual system fixed; derive 5–7 materially different structures from content/task/behavior, order by resonance. For a genuinely open whole page/screen/flow run `"<skill-base-dir>/scripts/impeccable" concept-seed --scope surface --mode <mode>`. It deals three structures to user; decision-page cards equal salience, lead kicker THE ROLL, steer/re-roll. Types: `assigned` for dealt lead, `dealt` other dealt structure, `challenger` plus its `catalogId`/SOURCE ID. No canon/pick at surface scope. With image gen + comp-led, each card has `comp` under `.impeccable/mocks/decision/`, generated after serve in reading order; anchor with screenshot of representative existing page as reference image (harness tool or `impeccable generate-image --ref`), short prompt per visualize; prose paraphrase drifts, pixel references do not. Otherwise each card has `html` first-viewport skeleton; absent sketch falls back to `wireframe` via `impeccable serve-question --schema`. Locking comp approves comp-led and discharges visualize's three-option round; lock sketch/wireframe means code-led, locked sketch is composition to match. Never run for local extension or precisely specified narrow ask.
- New/replacement world: (1) name unique mechanism, audience's real scene/cultural home, what first surface proves; note category standard and predictable opposite, both excluded as rut. If brief/product name/titled artifact/metaphor paints picture, literal reading gets at most one candidate. (2) list seven concrete world-based systems/artifacts/places/rituals: for each resonance/mechanism rationale and look (ground/main colours/type voices/signature), ordered by resonance. Include graphic/screen traditions. Operate/Read sources may come from any audience world but never the tools it operates (terminal/scope/control panel is costume); named abstract system is concrete. Persuade/Experience tools count toward rut: at most one. Ask physical-object and pre-web equivalents; near-duplicates count once. More than three sharing material family means dig until at least three families. (3) make complete directions joining reusable visual world + concrete first-surface experience.
- (4) Mandatory `concept-seed --scope direction --mode <mode>`; no substitute/skip. Writing artifact code before script run and its assignment acknowledged is a contract violation, regardless of harness/model/time pressure. It assigns direction/deals challengers. Fuse challenger (form/system grammar) with product (all facts; clarity wins); weigh on exactly two axes: audience identification and product clarity. Decide verdict before borrowing: wins = beats assigned on both, build candidate; competitive = holds one, full alternate; declined = loses both. Declined challenger is not spent: name one missing system discipline and raise assigned direction before presentation. Donate ambition/system discipline, never challenger clothes; component treatment is clothes, motif is costume, one world owns page. Each raise is explicit line named for donor.
- (5) Present one direction already raised, with visible named lines: world, first viewport, visitor path, signature interaction, cross-surface reach, honest risk. Winners/competitive full alternates with QUALITY BAR cards/case line; declined compact quiet demoted row with verdict + what kept, never full-size/silently dropped, still adoptable. Verdict informs, never preempts choice. At most three full-card challengers; if more dealt, strongest three enter, rest wait in re-roll pool with one-line note. Removing from hand requires named, disclosed product-truth failure. Number of full cards follows verdicts, not user's requested count; honestly explain smaller hand and offer re-roll; never promote declined merely to fill. Standing exit does not count once user has seen/rejected it, remains quiet door. Add exactly one IMPECCABLE’S PICK card for top grounded candidate if not assigned, same anatomy, honest familiarity risk. Never two picks or ranked list; pick never leads; if assigned is your top choice note it topped list. Re-roll has steer registers plain (fresh hand/same spread), safer (remaining conventional grounded + canon against named competitors), bolder (foreign forms only, full commitment); user, not agent, chooses. Re-run seed with `--register <value>` and next `--reroll`; “bolder”/“safer” while round open means registers, not commands. Two channels: decision page cards/boards; structured tool names/one-liners, option list assigned/pick/win+competitive/standing exit last; declined folded into assigned description preserving raised lines.
- Standing exit is permanent quiet category standard: never recommend, weigh against roll, or let it soften dealt directions. If user chooses it, convention becomes commitment: ask once for 2–3 products to sit alongside, craft bar matches theirs, execute canon faithfully without irony/smuggled quirk; record standing preference as brand commitment in PRODUCT.md. Re-roll removes all shown directions; after two consecutive re-rolls ask missing quality. Agent re-roll only for named factual ground that assigned cannot carry truth/task; never taste. User/brief-pinned direction always wins. Resolve collisions field-by-field, preserving pins; in open dimensions assignment still binds topology/controls/state vocabulary/ritual; translate materials conflicting with pinned world/PRODUCT commitment and name translation. Look mismatch is not reason to reroll.
- Decision payload: assigned first (raised lines), pick if any, dealt challenger alternates with QUALITY BAR/verdict/kept lines, re-roll registers, steer, canon enabled, `buildPath` default + `toggle:true` if image gen. Degraded no-challenger round still uses page, one text-only card + reroll. Every card declares identity: `assigned`, `pick`, `challenger`, `grounded`, or `dealt`; challenger carries concept-seed's SOURCE `catalogId`, not own ID. `--start`/`--update` refuse missing identities. Equal anatomy: thesis, palette, materials, first viewport, honest risk, challenger case lines (`--schema` is exact); page demotes declined automatically. Catalog image is labeled inspiration, never build promise. Include `canonCard` as honest category-standard card, same anatomy, subordinate.
- Serve choice via `serve-question --start --payload <file>` (`--schema` first); daemon prints URL/key; open in-app browser, then system opener, then display URL. Collect `--wait --key <key>`, repeat while exit 3; ANSWER JSON. `{"optionId":"reroll"}` keeps server/tab open: rerun concept-seed same scope/mode + `--from <seed-key> --reroll <n>` (1 first, increment), make payload, `--update --key <same key> --payload <file>`, then wait same key. Never start second server or fallback to chat. Exit 4 (closed unanswered): re-present once via structured tool; no answer means unattended assigned direction, state assumptions. Shell that can block may run script without `--start` (auto-open/block). If harness cannot hold `--wait`, do not start page; use structured tool and disclose substitution in first reply. Poll a still-running session; rerun wait only after it exits without answer. Only start exit 2 or wait check before start routes to structured fallback; do not retry other errors.
- Decision comps: with image gen, every card including canon declares path under `.impeccable/mocks/decision/`; serve first, then generate. Load visualize.md before first prompt. Comp is north-star, requested surface as real page, first viewport + start of next section, short prompt format, real product name/content, no invented commercial claims, card's own palette/type/material, full commitment. Template skeleton remains template under any skin, including pick. `serve-question --start`, `--update`, comp flip prints `NEXT read <path>/visualize.md`; do so before prompt. `--wait` flags missing `.png.json` prompt sidecar as `COMP SIDECAR MISSING`, stale slot as `COMP STALE`. Equal fidelity per card, one surface/aspect. Portrait for native/mobile-first; landscape desktop web. Reading order: assigned, pick, full hand, canon, each saved with prompt sidecar; no comp for declined challenger. Up to four parallel asset-producer subagents, one per card with packet (card fields, source images if NEXT names them, PRODUCT.md, frame, visualize path, MODE RULES COMPS block verbatim, output path); inline-regenerate empty slot on return; drop empty slots when user answers. Without agents generate in main thread. Chosen comp becomes comp option one for comp-led; code-led comp returns as critique reference. Unchosen comps are spent hand, no approval. Without image gen, palette chips/facts suffice; catalog thumbnails demoted.
- Build path: not asked inside a round; page toggle handles exception. Operate/Read always code-led. Persuade/Experience uses `.impeccable/config.json` `buildPath`; local `.impeccable/config.local.json` wins; absent setting defaults comp-led with image generation. Follow PRESENTATION line. Payload has `buildPath: {"value": <default>, "toggle": true}`; answer includes `buildPath`, `buildPathFlipped`. Flip binds session, not persisted; only ask once after flip for Persuade/Experience if project has no setting. Init records preference where possible. Flip on Operate/Read never offered for persistence. Answer yes or “no, just this once” both write config (affirmed flipped value or value flipped away from); untouched toggle means no offer. User verbal request changes config without asking. Comp-led approved comp is law, before build, finish audits; fix rounds expected, cannot silently skip. Code-led has no comp and no apology: locked sketch composition is build/finish target; QUALITY BAR calibrates finish, ambition in FIRST VIEWPORT + named interaction/motion grammar. Code-led may have flip-reserve comp path; midround flip returns BUILD PATH FLIPPED; generate open card comps then resume; flip back free. No image gen = code-led, no toggle; structured-tool fallback follows printed path, no toggle.
- Catalog world is working system, not mood reference: carry palette/material/type/composition/topology/controls/state/responsive rules as mode allows. Open QUALITY BAR board + hero for chosen world on choice; bar calibrates finish/commitment/art direction, never composition. Every roll direction must be viable/truthful, real palette/component family, distinctive composition/product-specific experience, feasible assets/tools/performance; replace truth-failing candidate before roll. In greenfield, author illustrative data, label synthetic where mistaken for real; give replacement-assets list. Never invent commercial/factual claims (prices, customers, benchmarks, endpoints, nonexistent capabilities). Do not refuse bold direction just because demo data not yet exists.
- Mode rules are printed by concept-seed and govern all direction/cards/comps; prevail over shared guidance. If pinned direction bypasses seeding, read mode-persuade for Persuade/Experience, mode-operate, or mode-read.

**4. Commit world.** Pick color strategy before colors: Restrained (world-tinted neutrals + one accent), Committed (one saturated color on 30–60% surface), Full palette (3–4 named roles), Drenched (surface IS color). Persuade/Experience can choose bolder if brief allows. Color at page scale, whole-region fields not scattered accents. Dark/light never default: write physical scene sentence (who/where/light) to force decision. Faces: Operate/Read can use system/workhorse UI faces; Persuade/Experience needs POV faces. Training-data defaults listed (Fraunces, Playfair Display, Cormorant, Lora, Crimson, Newsreader, Syne, Space Grotesk, Space Mono, IBM Plex, Inter-as-display, DM Sans, DM Serif, Outfit, Plus Jakarta Sans, Instrument Sans) require specific reason no other face suffices; subject association (books serif, bookstore hand-lettering, tech mono) is never reason.
- Calibration defaults legitimate only when brief calls for them: warm cream + high-contrast serif + terracotta/signal red; near-black + neon + glow; broadsheet hairlines/italic serif/tracked mono; flat saturated ink/black boxes/hard offset shadows/heavy condensed display. **Cognitive load**
- Intrinsic task load cannot be removed, structure it (steps/scaffolding/progressive disclosure/grouping). Extraneous load is design waste; eliminate ruthlessly (confusing navigation, unclear labels, clutter, inconsistency, unnecessary steps). Germane learning load is good (gradual disclosure, consistent learnable patterns, feedback, action-based onboarding).
- Eight checklist items: single focus; chunking ≤4 items/group; related visual grouping; clear hierarchy; one decision at a time; ≤4 visible options at decision; no memory bridge across screens; progressive disclosure. Count failures: 0–1 low, 2–3 moderate/address soon, 4+ high/critical.
